### v1.6.0 · 捕获窗口泄漏修复 + 透明度真相（2026-10-02 接手后）

**修复**
- [x] **Bug-016 捕获窗口泄漏**（★ 本项目最隐蔽的资源泄漏）
  - 现象：拖动几次之后拖不动；模型移动时「到处闪/瞬移」
  - 根因：`detachOverlay()` 只移除渲染窗口，**从未调用 `removeTouchCatcher()`**。
    Service 停止后进程通常仍存活（Android 保留缓存进程），窗口不随 token 消失 →
    残留捕获窗口继续可触摸，而它的 `OnTouchListener` 闭包指向**已销毁的旧 Service 实例**
    （`webView` 已为 null）→ 触摸被吞掉却什么都不做。
    Android 在 `ACTION_DOWN` 时绑定整个手势序列，所以撞进残留矩形的手势**整段**失效。
  - 实测：3 轮「停→启」后 `dumpsys` 里累积出 **5 个捕获窗口**（应为 1 个）
  - 修复：`detachOverlay()` 中补 `removeTouchCatcher()`
  - 验证：连续 3 轮启停，捕获窗口 `1 → 0 → 1`，**零泄漏**

**新增约束（架构层，已写入 00_交接总纲 §五 第 6 条）**
- [x] **全屏穿透式悬浮窗的不透明度硬上限为 0.8**
  - 现象：整体透明度拉到 100% 仍然「有点透明」
  - 根因：Android 12+ 对带 `FLAG_NOT_TOUCHABLE` 的系统悬浮窗强制压低 alpha。
    系统原话（`logcat`）：
    `App com.live2d.overlay has a system alert window (type = 2038) with FLAG_NOT_TOUCHABLE
     and LayoutParams.alpha = 1.00 > 0.80, setting alpha to 0.80 to let touches pass through`
  - **推翻了 v1.4.0 的结论**：当时记为「模型自带 alpha 的观感」，属**误判**
  - 已排除的两条修复路径（都实测过）：
    1. 反射 `touchableRegion` / `setTouchableRegion` → **本机不存在该成员**
       （枚举 `WindowManager.LayoutParams` 全部触摸相关成员：只有 5 个 `FLAG_*` 常量，方法为空）
    2. `settings put secure maximum_obscuring_opacity_for_touch 1.0` + **重启** → **仍压制到 0.8**
  - 结论：**0.8 是本机硬上限**。要 100% 只能改用「把模型渲染进可触摸的包围盒窗口」，
    代价是包围盒矩形内的触摸不再穿透到桌面（见 §二 P1-6，**待用户决策**）

**变更**
- `versionCode` 6 → 7，`versionName` 1.5.0 → 1.6.0

### v1.7.0 · 拖动抖动根治 + 动作库外置 + 透明度定案（2026-10-02 接手后）

**修复**
- [x] **Bug-017 拖动时模型闪现跳动的真正根因**（★ Bug-013 只修了一半）
  - 现象：拖动过程中模型到处闪 / 跳动（Bug-016 修完泄漏后**仍然存在**）
  - 根因：`forwardTouchToWebView()` 用 `ev.x + catcherOffsetX` 换算屏幕坐标。
    `ev.x` 是「事件生成那一刻」相对捕获窗口的**局部**坐标，而偏移量是
    `syncTouchCatcher()` **刚发布**的值 —— 但 `updateViewLayout()` 要经 Binder
    **异步生效**。窗口移动后的那几帧里，「新偏移 + 旧局部坐标」算出的坐标会整体
    偏掉一个位移量。
    拖动时捕获窗口**每帧都跟着模型移动**，于是形成自激振荡：
    窗口移动 → 坐标偏掉 → 页面按**增量**（`model.x += x - pointerLastX`）
    又把模型挪一次 → 命中区再移动 → 再偏掉…每一次偏差都**永久留在模型位置上**。
  - 修复：改用 `ev.rawX / ev.rawY`（输入系统给的**屏幕**坐标），与窗口位置和
    我们的记账彻底解耦。同时删除已无用的 `@Volatile catcherOffsetX/Y/ScaleX/Y`。
  - 验证：单指注入拖拽 4 步，命中区 `L = 220 → 185 → 149 → 114`，
    **步长恒为 35~36 px，零跳变**；理论值 `80 × 712/1600 = 35.6`，与手指 1:1 跟手

**新增**
- [x] **P2-3 动作库外置为 JSON** —— 换模型免改代码
  - 新增 `assets/live2d/model-profile.json`：动作库（`set`/`clear` 数据表）+ 水印参数 + 裁切参数
  - 页面：`MODEL_ACTIONS` 由 `const` 改 `let`，新增 `window.__mikuLive2DApplyProfile(json)`
    把 JSON 的 `set`/`clear` 表编译成与内置动作同构的函数；水印参数也改为可覆盖
  - Android：`loadModelProfileJson()` + `pushModelProfileToPage()`，在 `onPageFinished` 注入
  - **加载优先级**：`<模型目录>/model-profile.json`（可热改）→ `assets/live2d/model-profile.json` → 页面内置硬编码兜底
  - **为什么由原生读文件再注入而不是页面 fetch**：页面以 `file:///android_asset/` 加载，
    对同目录 JSON 发 fetch/XHR 受 file:// 同源策略限制，各 ROM 行为不一致
  - 校验：JSON 非法 / 文件缺失时**保持内置兜底**，绝不把动作库清空（否则短按彻底没反应）
  - 验证：`[MOTION] 使用内置模型档案 | bytes=1866` → `[JS:MOTION] 模型档案已应用 | id=miku/7项`

**决策落地**
- [x] **P1-6 透明度走方案 A** —— 滑条语义改为诚实的 0~100% → 0~0.8
  - `OverlayService.MAX_OVERLAY_ALPHA = 0.8f` + `sliderToAlpha()`；两处 alpha 赋值统一走它
  - 界面透明度滑条下新增说明文案（`tv_alpha_hint`）
  - 附带收益：alpha 恒 ≤ 0.8，**不再触发系统的压制逻辑**，logcat 里那条告警消失
  - 验证：渲染窗口 `alpha=0.8`，且无 `setting alpha to` 告警

## 四、明确的非目标

以下项**已评估并主动排除**，接手后不必再尝试：

| 项 | 排除原因 |
|---|---|
| 单窗口动态翻转 `FLAG_NOT_TOUCHABLE` | Android 输入管线在 `ACTION_DOWN` 时就绑定手势序列，**已实测证伪** |
| 通过 adb 注入多点触控做自动化 | production build 无 root，`sendevent` 与 `input motionevent` 均不可行 |
| 读取 VTube Studio 热键（`miku.vtube.json` 的 `Hotkeys`） | VTS 私有机制，外部 App 无法读取或执行 |
| 用 `content://` URI 加载模型 | 无法访问同目录兄弟资源（`.moc3` / 纹理），必须用 `file://` 相对路径 |
| 命中判定改用 `renderer.render()` 读像素 | 会污染主帧缓冲 → 点击闪色（Bug-001） |
