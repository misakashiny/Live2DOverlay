# Live2D 桌面悬浮窗 —— 工程说明（v1.5.0）

> 完整迭代历史、Bug 维修记录与后续路线见 **《Live2DOverlay_迭代大纲.md》**。
> 本文只讲「这是什么 / 怎么跑起来 / 有哪些坑」。

## 一、这是什么

一个可编译、已产出 APK 并**真机验证通过**的 Android 工程。

它在桌面上叠加 Live2D 模型，并实现了**区域化触摸**：

- **模型范围内** —— 可点击（触发动作 + 点击特效）、可长按（解锁拖拽 + 抓住脉冲）、可拖拽移动、双指捏合缩放、视线跟随手指；
- **模型范围外** —— 触摸完全穿透到桌面，不干扰任何正常操作。

技术路线来自对 MikuCarLauncher 的逆向还原，叠加方式经氢桌面「悬浮地图」机制验证。

## 二、核心架构与交互（截至 v1.5.0）

### 核心架构 —— 两窗口分离

| 窗口 | 尺寸位置 | 触摸标志 | 职责 |
|---|---|---|---|
| **渲染层** | 全屏 MATCH_PARENT | 含 `FLAG_NOT_TOUCHABLE` | 只负责画 |
| **捕获层** | 恰好等于模型包围盒 | 不含 `NOT_TOUCHABLE` | 只负责收触摸 |

交互区域之外**从来不属于任何窗口**，触摸天然落到桌面，无需任何时序博弈。

> **为什么不用单窗口动态切换标志**：Android 的输入管线在 `ACTION_DOWN` 派发时就把整个
> 手势序列绑定给了目标窗口，事后摘除 `FLAG_NOT_TOUCHABLE` 不会让已注入的 DOWN
> 重新路由到下层。该方案已实测证伪（80ms / 220ms 两种挂起时长均失败）。

验证方式：
```bash
adb shell dumpsys window windows | grep -A4 "com.live2d.overlay}:"
# 渲染层 fl=... NOT_TOUCHABLE ...      ← 穿透
# 捕获层 fl=... (无 NOT_TOUCHABLE) ... ← 可触摸
```

### 交互能力

| 手势 | 行为 | 起始版本 |
|---|---|---|
| 移动手指（无需按下） | 视线/头部跟随 | v1.1.0 |
| 单击模型 | 播放动作（默认随机，可切顺序轮播）+ 点击特效（涟漪 + 星光） | v1.1.0 / 特效 v1.5.0 |
| 长按 400ms | 解锁拖拽模式，并触发 260ms「抓住」缩放脉冲反馈 | 拖拽 v1.2.0 / 脉冲 v1.5.0 |
| 拖拽 | 移动模型，拖拽中即做边界夹取，松手后**持久化位置** | v1.2.0 |
| 松手靠近左右边缘 | easeOutCubic 平滑吸附停靠（仅水平方向） | v1.5.0 |
| 双指捏合 | 缩放模型 0.3~3.0 倍并持久化 | v1.5.0 |

> 短按 / 长按的区分用「位移阈值 + 长按计时」双条件：长按到时只置 `dragArmed`，
> 手指随后移动才真正进入拖拽；若长按后直接抬手，仍按一次普通点击处理
> （避免「按了半天没反应」）。

### 开关

界面「开关与自启」区块的**「启用悬浮窗」**总闸，加上「触摸交互」子开关：
- **开**（默认）—— 模型可交互，其余区域穿透；
- **关** —— 回到全屏纯装饰模式，完全不干扰桌面。

切换走 `ACTION_SET_TOUCHABLE`，**无需重载页面**（避免重新加载模型）。

「交互反馈（v1.5.0）」区块另有三个开关，均通过 `ACTION_DEBUG_JS` 注入页面接口热切换：

| 开关 | 页面接口 | 说明 |
|---|---|---|
| 点击特效 | `__mikuLive2DSetOption('fx', 0/1)` | 关闭后短按不再播涟漪/星光 |
| 边缘吸附 | `__mikuLive2DSetOption('snap', 0/1)` | 关闭时同时撤销进行中的吸附补间 |
| 动作按顺序轮播 | `__mikuLive2DSetActionCycle(0/1)` | 关闭=随机，开启=逐个播放便于验证动作库 |

## 三、快速开始

### 编译

```bash
cd Live2DOverlay
export JAVA_HOME='C:\Program Files\Eclipse Adoptium\jdk-21.0.12.101-hotspot'
export ANDROID_HOME='C:\Android\Sdk'
./gradlew :app:assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

> 不要加 `--offline`（AGP plugin marker 未缓存）；构建必须前台执行。

### 安装与首次配置

```bash
adb install -r app-debug.apk
adb shell appops set com.live2d.overlay SYSTEM_ALERT_WINDOW allow
adb shell appops set com.live2d.overlay MANAGE_EXTERNAL_STORAGE allow
adb shell pm grant com.live2d.overlay android.permission.POST_NOTIFICATIONS
```

在设备上打开「Live2D 桌面」App，依次完成：

1. **授予悬浮窗权限** —— 点「去授权悬浮窗」，在系统设置中打开开关；
2. **授予所有文件访问权限** —— 点对应按钮（Android 11+ 必需，否则 WebView 无法用 `file://` 读模型）；
3. **选择模型** —— 任选一种：
   - 「扫描默认目录」：把模型放进 `/sdcard/Live2DModels/`，一键识别；
   - 「选择模型所在目录（推荐）」：**必须选目录**，不能选单个 json；
   - 「手动输入路径」：兜底方案；
4. 打开底部**「启用悬浮窗」**开关。

### 模型目录要求

Live2D 模型是「描述文件 + 兄弟资源」的集合，目录结构如下：

```
miku/
├── miku.model3.json             入口（选择此文件所在目录）
├── miku.moc3                    网格数据
├── miku.4096/                   纹理目录（内含 texture_00.png 等 6 张）
├── miku.physics3.json           物理演算
├── miku.cdi3.json               参数名映射
├── *.exp3.json                  表情
└── *.motion3.json               动作
```

> 必须用 `file://` 相对路径访问，`content://` URI 无法读取兄弟资源 ——
> 这是放弃 SAF 单文件选择器的根本原因。

### 日志系统（v1.3.0 起）

统一格式 `[HH:mm:ss.SSS][MODULE][LEVEL] message | k=v k=v`，
5 级（`V/D/I/W/E`）、10 个模块（`SVC/CFG/BRIDGE/UI/RENDER/TOUCH/MOTION/PARAM/WM/FX`）。
页面侧日志经 `MikuLive2DAndroid.log()` 走桥接上报，**不要同时 `console.log`**
（会造成双通道重复记录，v1.3.0 Bug-011）。

界面「运行日志」面板支持：级别过滤、模块/关键字过滤、实时滚动、
长按单行复制、清空、导出文本、导出 JSON。
级别选择持久化到 `OverlayConfig.logMinLevel`（「全部」用哨兵值 `"ALL"` 存档）。

## 六、URL 参数协议

```
live2d_decor.html?model=<file://...>&dw=2560&dh=720&cx=&cy=
                 &scale=&quality=&fps=&clip=0&clipBottom=
                 &touch=1&autoPos=1&watermark=1&cycle=0&fx=1&snap=1
```

| 参数 | 含义 |
|---|---|
| `touch=0/1` | 是否启用触摸交互 |
| `autoPos=1` | 触摸模式下由页面自动落位（此时不下发 `cx/cy`，坐标滑条置灰） |
| `watermark=0/1` | 是否隐藏模型自带水印 |
| `cycle=0/1` | 动作是否按顺序轮播（v1.5.0） |
| `fx=0/1` | 点击特效（v1.5.0） |
| `snap=0/1` | 边缘吸附（v1.5.0） |

> 三个 v1.5.0 参数在页面侧用 `let` 而非 `const` 接收，
> 以便 Android 侧运行时热切换而无需重载页面。

## 七、★ 实现中踩过的关键坑

### 1. 坐标系换算（WebView 悬浮窗必踩）

`dispatchTouchEvent` 的 `e.x/e.y` 是 **View 像素**（本机 2560×1494），
而页面的 `window.innerWidth` 是 **CSS 像素**（本机 1138×664）—— WebView 按
devicePixelRatio 缩放。**相差约 2.25 倍**，直接比较必然失败。

→ 页面把 `vw/vh` 随包围盒一起上报，Android 侧按 `cssX = viewX * (vw/viewW)` 换算。

### 2. 粘滞保护必须用状态而非时间窗口

第一版用 `now - lastHitAt < 400ms`，导致一次命中后数百毫秒内所有落点都判为命中，
表现为「桌面点不动」。→ 改为 `touchSequenceActive && sequenceStartedInside` 双状态。

### 3. 开关字段必须从持久化配置读取

`touchEnabled` 字段初版默认 `true` 且从不读 `config`，导致关闭「触摸交互」后
`onHitAreaChanged` 仍重建捕获窗口，纯穿透模式失效。

### 4. WebView 对合成 MotionEvent 派发 touch 而非 pointer

两套事件都要接；CSS 需 `touch-action: none`，否则拖拽变页面滚动。

### 5. 拖拽期间禁止待机逻辑改写位置

`updateDefaultIdle()` 里加 `if (!dragging)` 守卫，否则「拖着拖着弹回去」。

### 6. 桥接命名必须与页面逐字一致

页面引用 `window.MikuLive2DAndroid`，Java 侧 `addJavascriptInterface` 的 name
必须完全相同。**不一致不会编译报错，而是运行时静默失效**。

### 7. Kotlin 嵌套块注释

Kotlin 支持 `/* */` 嵌套。文档注释里写 `*.png` 这类 `/*` 组合会导致整个文件
「未闭合注释」编译失败。写注释时避开 `/*` 相邻。

### 8. 权限申请递归

`registerForActivityResult` 回调里**绝不能**调用会再次触发同一 launcher 的方法。
「状态刷新」与「权限申请」必须解耦，否则 `StackOverflowError` 首次启动即闪退。

### 9. 长生命周期回调里禁止捕获会变化的局部变量（v1.4.0）

`setOnTouchListener` 的 lambda 捕获了 `syncTouchCatcher` 的入参 x/y，
而捕获窗口在拖拽中持续移动 → 转发偏移停在旧值 → 坐标累积漂移。
表现为「拖几下就失效 + 拖动时模型乱闪」。
→ 改 `@Volatile` 字段实时发布，回调每次读**当前值**。

### 10. 开关的「写入→传输→消费」三段闭环（v1.4.0）

`overlayAlpha` 曾经只写不读：UI 能存、日志能打，但 `buildPageUrl()` 没下发、
窗口也没应用 → 滑条完全无效。**新增设置项必须逐段验证**，
只写进 `SharedPreferences` 不等于功能可用。

### 11. 双指手势必须在原生捕获层识别（v1.5.0）

`forwardTouchToWebView()` 只取 `ev.x/ev.y` 构造**单点** MotionEvent，
页面永远收不到第二根手指。→ pinch 在原生侧算好缩放值，
页面只暴露 `__mikuLive2DSetUserScale(s)` 落地。
第二指落下时须先 `__mikuLive2DCancelPointer()` 撤销页面的单指拖拽，
否则「一边放大一边乱飘」。

### 12. 带进行中状态的开关，关闭时必须收尾（v1.5.0）

关闭「边缘吸附」若只置 `false`，进行中的补间动画仍会继续把模型拽向边缘。
凡是 ticker 里每帧读取并改写模型属性的状态变量，关开关时都必须一并清除。

### 13. 合成事件的坐标字段不可靠（v1.5.0）

同一处理函数被 `pointer` / `touch` / `mouse` 三套通道复用，
其中 touch 通道的 `handleUp()` 以 `onPointerUp({})` 调用 —— 抬手事件里没有坐标。
`FX.tap(e.clientX, e.clientY)` 因此得到 `NaN`，特效不可见。
→ 改用自维护的 `pointerLastX / pointerLastY`。

## 八、已知限制

1. **当前模型无内置动作与表情段**。`miku.model3.json` 只声明了
   `Moc / Textures / Physics / DisplayInfo / Groups`，没有 `Motions` 与 `Expressions`，
   所有动作表情靠**参数驱动**（`Param125` 圈圈、`Param130` 脸红、`Param132` 前倾、
   `Param133` 拿葱、`Param134` 唱歌、`Param135` 比心、`Param136`+`Param131` QQ 人…）。
   `MODEL_ACTIONS` 动作库需按模型逐个逆向，换模型要重新适配。
2. **模型动作库尚未外置**。当前硬编码在 `live2d_decor.html` 里，
   后续计划抽成 `model-profile.json` 实现模型无关。
3. **触摸热区精度**：命中判定用几何近似（忽略模型旋转的微小平移），
   模型大幅旋转时可能有 ±6px 误差。
4. **调试通道未设防**：`ACTION_DEBUG_JS` 可注入任意 JS，仅适合 debug 构建，
   正式发布前建议加 `BuildConfig.DEBUG` 判定。
5. **双指缩放仅完成代码实现与单指回归验证**，尚未在真机上人工确认手势本身
   （原因见《迭代大纲》§6.5：production build 无 root，adb 无法注入多点事件）。
