# 氢桌面「悬浮地图」功能逆向分析 — 悬浮窗方案可行性验证

分析对象：`氢桌面1.3.0.apk`（`com.mcar.auto` v1.3.0）
目的：用户提出「氢桌面里的悬浮地图功能，本质就是悬浮窗方案」，验证该判断是否成立，
以及能否照此思路给车机接 Live2D。

---

## 一、结论：判断成立，而且比预想的更完整

**氢桌面确实有完整的悬浮窗能力，悬浮地图就是用它实现的。**
这意味着「给车机接 Live2D 用悬浮窗方案」不只是理论可行 ——
**这台车机上已经有一个在跑的、同机制的参照实现**，且权限已经授予过。

更理想的推论：**如果氢桌面已经拿到了 `SYSTEM_ALERT_WINDOW` 权限，
你的 Live2D 悬浮窗 App 依然需要自己申请一次**（权限是按包名授予的，不能复用）。
但用户已经有过授权操作经验，引导成本大幅降低。

---

## 二、证据链（全部来自本次 APK 静态分析）

### 2.1 权限已声明

```xml
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW"/>
```

位于 Manifest `line=55`。这是悬浮窗的准入前提。

### 2.2 悬浮窗布局确实存在（资源表实锤）

| 资源 ID | 名称 | 说明 |
|---|---|---|
| `0x7f0b0112` | `layout/widget_float_map` | **悬浮地图**（对应 `res/ua.xml`） |
| `0x7f0b011f` | `layout/widget_music_lrc_float` | **悬浮歌词**（对应 `res/ZK.xml`） |
| `0x7f0b0113` | `layout/widget_hang_datetime` | 悬挂时钟/日期 |
| `0x7f0b0073` | `layout/fragment_set_float_app` | 「悬浮应用」设置页 |
| `0x7f0b0074` | `layout/fragment_set_float_button` | 「小白点」设置页 |
| `0x7f0b0075` | `layout/fragment_set_float_music` | 悬浮音乐设置页 |
| `0x7f0b0076` | `layout/fragment_set_float_music_lrc` | 悬浮歌词设置页 |

### 2.3 悬浮地图布局的内部结构（`res/ua.xml` 实测）

```xml
androidx.cardview.widget.CardView
  ├─ gravity / layout_gravity = 0x11        (CENTER)
  ├─ layout_width / height = -1             (MATCH_PARENT)
  ├─ cardCornerRadius = 1.0dp               ← 圆角很小，几乎直角
  ├─ cardElevation = 0.0dp                  ← 无阴影
  └─ children:
       ├─ com.mcar.auto.widget.ShapeBlurWidget   ← 自研圆角/形状裁切控件
       ├─ ImageView  (visibility=GONE)
       └─ LinearLayout
            └─ LinearLayout (圆形背景 + 固定宽高)
```

**关键点**：
- 用 `CardView` + `MATCH_PARENT` 撑满一个**独立的窗口容器**
- 有自研的 `ShapeBlurWidget` 负责圆角 —— 这与那条字符串完美对上：
  > `开启此功能可模拟返回键/可支持悬浮地图等应用圆角`
  > `(桌面设置-组件设置-地图设置-悬浮地图圆角-方案五)`
- 容器尺寸由外部 WindowManager 决定，所以内部才是 `MATCH_PARENT`

### 2.4 悬浮按钮（小白点）

`fragment_set_float_button` 里有：
```
androidx.appcompat.widget.SwitchCompat  text="显示小白点"
```
Android 生态里「小白点」= 触摸辅助悬浮球（类似 iPhone AssistiveTouch）。
配合 Manifest 里的：
```xml
<service android:name="com.mcar.auto.service.FloatButtonService"/>
```
→ **`FloatButtonService` 就是承载悬浮球的 Service。**

### 2.5 「画中画」组件（重要旁证）

字符串表 `String #1819`：
```
氢桌面(画中画)
```

这条是**系统设置里显示的组件标签**。它在暗示：氢桌面把一个组件注册成了「画中画」形态。
配合 Manifest 里的：
```xml
<activity android:name="com.mcar.auto.activity.VirtualDisplayActivity"
          android:exported="false"/>
```

**`VirtualDisplayActivity` + 「画中画」标签** → 这是用来做**跨应用窗口嵌入 / 虚拟显示**的能力。

### 2.6 无障碍服务兜底

```xml
<service android:label="氢桌面(模拟返回/悬浮模拟圆角)"
         android:name="com.mcar.auto.service.accessibilityService"
         android:permission="android.permission.BIND_ACCESSIBILITY_SERVICE"
         android:foregroundServiceType="0x00000008"/>
```

`foregroundServiceType=8` = `FOREGROUND_SERVICE_TYPE_SPECIAL_USE`。
这个无障碍服务同时负责「模拟返回键」和「悬浮圆角」——说明**悬浮窗的圆角处理需要无障碍配合**
（第三方应用浮窗无法直接改别人的窗口圆角，得靠无障碍注入或覆盖层伪造）。

### 2.7 高德地图 SDK 已集成

```xml
<meta-data android:name="com.amap.api.v2.apikey"
           android:value="87b7a3af17c44973d40b53a0453273da"/>
```
→ 悬浮地图用的是**高德 SDK**，不是简单截图。

## 三、它的悬浮窗方案 vs 你的 Live2D 方案

| 维度 | 氢桌面悬浮地图 | 你的 Live2D 悬浮窗 |
|---|---|---|
| 窗口类型 | `TYPE_APPLICATION_OVERLAY`（推断） | 同 |
| 权限 | `SYSTEM_ALERT_WINDOW` | 同（**需独立申请**） |
| 容器 | `CardView` + `ShapeBlurWidget`（圆角） | `FrameLayout`（**透明，无需圆角**） |
| 内容 | 高德地图 `MapView` | **透明 WebView** |
| 触摸 | 需要交互（拖地图、点按钮）→ 必然**不能**加 `FLAG_NOT_TOUCHABLE` | 需穿透 → **必须**加 `FLAG_NOT_TOUCHABLE` |
| 存活 | `FloatButtonService` / 前台服务 | 同（+ `BOOT_COMPLETED` 自启） |
| 圆形/圆角 | 靠 `ShapeBlurWidget` 精确裁切 | 交给 Live2D 模型的 alpha 通道，**不用裁** |

### 结论：机制相同，但你的场景更简单

差别只在两点，而且都对你有利：

1. **不需要圆角裁切**。氢桌面为了把矩形地图做成圆角，专门写了 `ShapeBlurWidget`，
   还要无障碍服务配合。而 Live2D 模型自带 alpha 通道，透明背景天然就是人形轮廓，
   **完全不需要任何裁切控件**。

2. **触摸策略相反**。悬浮地图必须接收触摸（不然没法操作地图），所以它不能加
   `FLAG_NOT_TOUCHABLE`。而你是纯展示美化，**必须加** `FLAG_NOT_TOUCHABLE`
   让触摸穿透到氢桌面。这一点反而比它更好做——不用担心触摸冲突。

## 四、最终方案（已由氢桌面实证可行）

```
┌────────────────────────────────────────────────┐
│  Live2D 悬浮窗 App（你的，独立进程）             │
│   WindowManager.addView(                       │
│     Live2DFloatView,                           │
│     TYPE_APPLICATION_OVERLAY,   ← 与氢桌面同型  │
│     PixelFormat.TRANSLUCENT,                   │
│     FLAG_NOT_FOCUSABLE                         │
│       | FLAG_NOT_TOUCHABLE      ← 关键：穿透    │
│       | FLAG_LAYOUT_NO_LIMITS                  │
│   )                                            │
│     └─ FrameLayout (透明)                       │
│          └─ WebView (transparent)              │
│               └─ live2d_decor.html             │
└────────────────────────────────────────────────┘
                    ↓ 叠加
┌────────────────────────────────────────────────┐
│  氢桌面（原封不动，悬浮地图等全部功能保留）       │
└────────────────────────────────────────────────┘
```

### 权限与声明

```xml
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE"/>
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>
```

> 参考氢桌面的做法：它把无障碍服务声明成了 `foregroundServiceType="0x8"`
> （`FOREGROUND_SERVICE_TYPE_SPECIAL_USE`）。Android 14+ 上如果你的前台服务
> 用途不明确，也需要这样声明，否则起不来。

### 权限引导（车机实操）

```kotlin
if (!Settings.canDrawOverlays(this)) {
    startActivity(Intent(
        Settings.ACTION_MANAGE_OVERLAY_PERMISSION,
        Uri.parse("package:$packageName")))
}
```

车机 ROM 常把这个开关藏得较深，建议做三级兜底：
1. `ACTION_MANAGE_OVERLAY_PERMISSION` 带包名（最精确）
2. 不带包名的 `ACTION_MANAGE_OVERLAY_PERMISSION`
3. `ACTION_MANAGE_APPLICATIONS_SETTINGS` 跳应用详情页，让用户手找

### 落地排序

| 顺序 | 事项 | 依据 |
|---|---|---|
| 1 | 最小闭环：悬浮窗 + 透明 WebView + 一个模型 | 机制已由氢桌面实证 |
| 2 | 加 `FLAG_NOT_TOUCHABLE` 并验证触摸穿透到氢桌面 | 你最担心的点，优先验 |
| 3 | 加心跳看护 + WebGL 丢失重建 | 车机 GPU 驱动不稳 |
| 4 | 加 `BOOT_COMPLETED` 自启 + 前台服务 | 车机熄火重启频繁 |
| 5 | 位置/缩放/夜间压暗设置页 | 提升可用性 |

---

## 五、一句话总结

> 用户的判断是对的：**氢桌面的悬浮地图就是标准悬浮窗方案**（
> `SYSTEM_ALERT_WINDOW` + `layout/widget_float_map` + `FloatButtonService` + 高德 SDK）。
> 这套机制**已在你这台车机上跑通**，说明 `TYPE_APPLICATION_OVERLAY` 可用、
> 悬浮窗在车机 ROM 上不被限制。
> 你的 Live2D 方案可以**完全照搬这套机制**，而且比它更简单 ——
> 不需要圆角裁切控件，只需加 `FLAG_NOT_TOUCHABLE` 做触摸穿透。
