## 一、项目定位

把 Live2D 模型以**悬浮窗**形式叠加在安卓桌面之上，实现两类能力：

1. **装饰层**：模型悬浮在桌面上，不遮挡桌面操作的正常使用；
2. **交互层**：模型身体范围内可触摸 —— 短按触发动作、长按拖动位置、视线跟随手指。

核心矛盾在于「**既要能触摸模型，又不能让悬浮窗吃掉整个桌面的触摸**」，本项目的全部架构演进都围绕这个矛盾展开。

## 二、系统架构

### 2.1 两窗口分离架构（v1.1.0 起确立，当前方案）

```
┌─────────────────────────────────────────────────────────┐
│ 渲染窗口 (Window #10)                                    │
│   · 全屏 fill×fill，alpha 可调                          │
│   · 标志含 FLAG_NOT_TOUCHABLE（永久不可触摸，只负责画）  │
│   · 内部是一个 WebView，加载 live2d_decor.html          │
└─────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────┐
│ 触摸捕获窗口 (Window #9)                                 │
│   · 尺寸/位置 == 模型包围盒（由页面上报，动态同步）      │
│   · 标志**不含** NOT_TOUCHABLE（负责收触摸）             │
│   · 收到 MotionEvent 后构造新事件注入渲染层 WebView      │
└─────────────────────────────────────────────────────────┘
```

**为什么不能用一个窗口**：Android 输入管线在 `ACTION_DOWN` 派发时就把整个手势序列**绑定**给目标窗口。事后翻转 `FLAG_NOT_TOUCHABLE` 不会让已注入的 DOWN 重新路由到下层。因此「常驻可触摸 + 运行时判断落点」的方案**已被证伪，不要再尝试**。

### 2.2 关键文件职责

| 文件 | 职责 |
|---|---|
| `OverlayService.kt` | 前台服务；窗口创建/销毁/重建；命中区盒同步；触摸注入 |

### 2.5 日志分层（v1.3.0）

```

   │  优先：window.MikuLive2DAndroid.log()   （结构化，走桥）
   │  兜底：console.log("L2D"+line)          （仅桥不可用时）

```

### 2.3 坐标系（高频踩坑）

`dispatchTouchEvent` 的 `e.x/e.y` 是 **View 像素**（本机 2560×1494）；
页面 `window.innerWidth` 是 **CSS 像素**（本机 1138×664）。两者相差约 **2.25 倍**。
换算必须由页面上报 `vw/vh`，Android 侧按 `cssX = viewX * (vw / viewW)` 处理。

### 2.4 配置持久化

路径：`shared_prefs/live2d_overlay_prefs.xml`
（**注意不是** `live2d_overlay.xml`，也不是 `overlay_config.xml`）

## 三、模型逆向结论（miku 模型）

### 3.1 模型文件结构

```
/sdcard/Live2DModels/miku/
├── miku.model3.json      入口（仅 Moc/Textures/Physics/DisplayInfo/Groups）
├── miku.moc3             9.5 MB 网格数据
├── miku.physics3.json    物理
├── miku.cdi3.json        141 个参数的显示名映射
├── miku.vtube.json       VTube Studio 工程文件（位置/热键/缩放）
├── miku.4096/texture_*.png   6 张 4096 纹理
├── Scene1.motion3.json   待机动作（2.667s 循环）
├── *.exp3.json           8 个表情文件
└── 模型使用说明.txt      作者版权说明
```

### 3.2 ★ 最重要的结论：模型没有 Motions / Expressions 段

`miku.model3.json` **完全没有** `Motions` 与 `Expressions` 字段。
因此运行时的 `motionList.length === 0`、`expressionList.length === 0`，
所有动作表情**只能通过直接设置参数值来驱动**。

### 3.3 参数映射表（从 cdi3.json + exp3.json 完整逆向）

| 参数 | 显示名 | 值 | 效果 |
|---|---|---|---|
| `Param133` | 大葱 | 1 | 拿葱（须 `134=0,135=0`） |
| `Param134` | 唱歌 | 1 | 唱歌（须 `133=0,135=0`） |
| `Param135` | 比心 | 1 | 比心（须 `133=0,134=0`） |
| `Param132` | 前倾 | 1 | 身体前倾 |
| `Param125` | 圈圈 | 1 | 头顶转圈 |
| `Param130` | 脸红 | 1 | 脸红 |
| `Param131`+`Param136` | QQ人 | 同时=1 | QQ 人形态（Add 混合） |
| `Param137` | 水印 | **1 = 隐藏** | **反向语义！详见 3.4** |

### 3.4 ★★ 水印的真相（R6 核心结论，经真机实验证实）

**这是一个此前被普遍误解的点，务必记住：**

- 屏幕上那层「玄宝 / 禁止直播·禁止商用 / 仅供 miku 二创使用 / 使用需要标明出处 /
  禁止二次上传、二次分发、改图牟利 / Non-commercial use only」的文字，
  是 **`Param137` 控制的一层独立贴图 Mesh**。
- 它的语义是 **反向的**：

  | Param137 值 | 水印表现 |
  |---|---|
  | `0`（模型默认） | **显示** |
  | `1` | **隐藏** |

- 因此 `水印.exp3.json`（内容为 `Param137 = 1.0`）实际是一个「**隐藏水印**」表情。
- VTube Studio 中「小键盘 1」是 VTS 的 Hotkey 绑定
  （见 `miku.vtube.json → Hotkeys[8]`：`Name=水印, File=水印.exp3.json`），
  **本 App 读不到 VTS 热键**，必须自己设参数。
- 因为模型每帧参数求值会把 `Param137` 重置为 0，**必须在 `beforeModelUpdate`
  钩子里持续压制**，在 `app.ticker` 里设置是无效的（时序问题）。
- ⚠️ 若某个模型把版权信息**直接烘焙在主纹理**上，任何参数都无法去除，
  只能编辑 PNG。本模型不属于此类。

### 3.5 「浮空」的真相（R5 结论）

模型文件中**没有**「让人站起来」的开关。早期看到的「浮空、模型小、发虚」，
实际主要成因是：**水印 Mesh 撑大了模型包围盒** → `getBounds()` 返回的高度偏大
→ `targetModelHeightPx / rawModelHeight` 算出的缩放偏小 → 视觉上又小又远。
水印隐藏后，模型即恢复正常大小与位置。

次要成因：`Scene1.motion3.json` 待机动作叠加的整体位移，以及
`miku.vtube.json → SavedModelPosition.Position = (x:-38.70, y:-66.67, z:0)`
（模型在 VTS 中本身被抬高）。

### v1.4.0（2026-10-02）· 透明度修复 + 拖动稳定性重构

**修复**
- **Bug-A：整体透明度完全无效**（详见 Bug-012）
  - 根因：`overlayAlpha` 是「只写不读」的死字段，`buildPageUrl()` 未下发、
    窗口未应用 → 100% 与 30% 视觉完全一致
  - 修复：在渲染窗口的 `LayoutParams.alpha` 上直接生效 +
    新增 `ACTION_SET_ALPHA` 通道支持实时调节（不重载页面）
- **Bug-B：拖动几次后失效 + 拖动时模型乱闪**（详见 Bug-013）
  - 根因：`setOnTouchListener` 的 lambda **闭包捕获了 `syncTouchCatcher` 的入参 x/y**，
    而捕获窗口在拖动中持续移动 → 转发给 WebView 的偏移量停留在旧值，
    坐标持续偏移累积，表现为闪烁；偏移足够大后命中判定失效
  - 修复：改用 `@Volatile` 字段 `catcherOffsetX/Y` + `catcherScaleX/Y`
    实时发布，触摸转发每次事件读取**当前值**
- **Bug-C：日志面板抢占外层滚动**（详见 Bug-014）
  - 根因：`refreshLogView()` 无条件 `fullScroll(FOCUS_DOWN)`，
    把外层 ScrollView 一起拽到日志区，导致用户无法操作上方的滑条/开关
  - 修复：新增 `isLogPanelVisible()` 判定，仅在日志区**实际可见**
    （可见高度 ≥ 1/3）时才自动滚动

### v1.3.0（2026-10-02）· 结构化日志系统

**目标**：把「靠 logcat 手工 grep」的排查方式，升级为「App 内可查看、可过滤、可导出」的快速迭代手段。

**新增**
- **统一日志核心 `L2DLog.kt`**（425 行）

### Bug-001 · 点击悬浮窗时闪一下轻微颜色

- **现象**：每次点击/触摸悬浮窗，画面短暂闪过异常颜色
- **根因**：命中检测函数 `isOpaqueAt()` 调用 `app.renderer.render(stage, viewport)`
  把整个舞台渲染到 **主画布**，随后 `drawImage` 抓取采样。
  Pixi 的 `render()` 会直接改写主帧缓冲，恢复 `stage.x/y` 也无法回滚，
  于是这一帧异常画面被用户看到。
- **修复**：彻底放弃 GPU 采样，改为**纯 CPU 几何判定**：
  1. 一级：落点是否在 `model.getBounds()` 屏幕包围盒内（外扩 6px 容差）；
  2. 二级：把落点反变换回模型局部坐标，比对局部不透明范围。
- **教训**：任何「为了辅助计算」而调用主渲染器 `render()` 的做法都是危险的。

### Bug-002 · 开启触摸后模型无法拖动

- **现象**：拖走模型后松手，模型立刻弹回原位；或拖动完全不跟手
- **根因**：待机逻辑 `updateDefaultIdle()` 每帧无条件执行
  `model.x = centerX * stageScaleX() + extraX`，其中 `centerX` 来自 URL 参数
  （设置页滑条值）。它与拖拽写入的位置互相打架。
- **修复**：
  1. 引入 `manualPositioned` / `touchManaged` 状态，一旦用户拖过或处于触摸模式，
     待机逻辑**不再覆写** `model.x/y`；
  2. `OverlayConfig.buildPageUrl()` 在触摸模式**不下发** `cx/cy`，改发 `autoPos=1`；
  3. 自动模式下初始落点取「屏幕水平居中、垂直 62%」；
  4. `applyLayout()` 同样尊重这两个状态，只改缩放不改位置。
- **教训**：**位置的所有权必须唯一**。多个来源同时写 `model.x/y` 必然打架。

### Bug-003 · 水印关闭不生效

- **现象**：尝试关闭水印无效果；模型说明写「按小键盘 1 关闭」
- **根因（三层）**：
  1. 「小键盘 1」是 VTube Studio 的 Hotkey，本 App 无法读取；
  2. 水印参数 `Param137` 是**反向语义**（1=隐藏，0=显示），
     按常规思路设 0 反而让水印**保持显示**；
  3. 在 `app.ticker` 里设参数**时序错误** —— 渲染链路是
     「ticker 回调 → `internalModel.update()`（参数求值）→ 渲染」，
     ticker 里写的值会被随后的 update 覆盖。
- **修复**：
  1. 取值改为 `Param137 = 1`；
  2. 压制逻辑挂到 `model.internalModel.on("beforeModelUpdate")`，
     这是参数求值完成后、变形计算前的唯一正确时机；
  3. 增加「隐藏模型水印」UI 开关（`KEY_HIDE_WATERMARK`，默认开），
     通过 URL 参数 `watermark=0/1` 控制。
- **验证**：真机审计显示 `Param137 idx=31 value=1`，截图确认水印完全消失。
- **教训**：**不要假设参数正负语义**，必须实测；Live2D 参数覆盖要挂在
  `beforeModelUpdate`，不能挂在 ticker。

### Bug-004 · 触摸穿透方案完全失效（v1.0 → v1.1 的关键障碍）

- **现象**：窗口设为可触摸后，整个桌面都被吃掉触摸；改为不可触摸则完全收不到事件
- **根因**：Android 输入管线在 `ACTION_DOWN` 派发时即把整个手势序列**绑定**到目标窗口。
  事后翻转 `FLAG_NOT_TOUCHABLE` 不会让已注入的 DOWN 重新路由。
- **修复**：改为**两窗口分离架构**（见 2.1）。
- **教训**：此路已封死，**不要再尝试单窗口动态翻转标志位**。

### Bug-005 · 命中判定粘滞（一次命中后全部命中）

- **现象**：点中模型一次后，接下来几百毫秒内任何落点都被判为「命中模型」
- **根因**：使用 `now - lastHitAt < 400ms` 时间窗口做去抖，
  导致命中状态被错误地延续。
- **修复**：改用**双状态机** `touchSequenceActive && sequenceStartedInside`，
  以手势生命周期而非时间窗口来界定。

### Bug-006 · 包围盒与触摸坐标不匹配

- **根因**：坐标系混淆（见 2.3）。
- **修复**：页面上报 `vw/vh`，Android 侧据此换算。

### Bug-007 · 关闭「触摸交互」后窗口仍可触摸

- **根因**：`onCreate` 中没有先读取持久化配置，`touchEnabled` 取了默认值。
- **修复**：`onCreate` 中 `touchEnabled = config.touchEnabled`。

### Bug-008 · `OverlayService.kt` 编译报 `Expecting member declaration`

- **根因**：Kotlin 中 `private fun x(): Int = A\n or B` 的 `or` 换行，
  被解析为表达式结束。
- **修复**：写成单行 `return A or B or C or D`。
- **教训**：Kotlin 表达式函数不要跨行放运算符。

### Bug-009 · 注释导致「未闭合注释」编译失败

- **根因**：Kotlin 嵌套块注释 —— 注释文本里出现 `*.png` 这种 `/*` 组合，
  会让编译器认为注释被提前嵌套。
- **修复**：注释中避免出现 `/*` 序列。

### Bug-010 · `am start-foreground-service` 报 `Requires permission not exported`

- **根因**：服务未声明 `exported`，adb 无法直接启动。
- **规避**：调试时通过 App 界面开关启动服务。

### Bug-011 · JS 日志被双通道重复记录（v1.3.0）

- **现象**：同一事件在日志里出现两条 —— 一条 `[JS:RENDER]`，一条
  `[BRIDGE][页面日志(兜底通道)]`。日志量虚增约一倍。
- **根因**：JS 侧 `LOG.write()` 同时执行了两个动作：
  ① `console.log("L2D" + line)` → 被 `onConsoleMessage` 捕获转发；
  ② `MikuLive2DAndroid.log(...)` → 经桥接直接写入。
  两条通道互不知情，各自落了一次。
- **修复**：改为**二选一**——优先走桥接（结构化字段、无字符串解析开销），
  仅当桥不存在（例如纯浏览器调试页面）时才回退 `console.log`。
- **修复效果（真机实测）**：同一批事件由 24 行降至 15 行，减少约 40%。
- **教训**：**新增一条日志通道前，先确认旧通道是否仍会转发同一内容**。
  「兜底通道」和「主通道」共存时，必须有明确的互斥判据，不能只是两条都写。

### Bug-012 · 整体透明度调节完全无效（v1.4.0）

- **现象**：滑条拖到 100% 和 30%，视觉上无任何区别；用户感知为「100% 还是有点透明」。
- **根因**：**字段只写不读**。
  - `OverlayConfig.overlayAlpha` 读写在 SharedPreferences，界面滑条正确写入；
  - `MainActivity` 滑条回调调 `pushLiveUpdate()`，走 `ACTION_REFRESH` → **重载页面**；
  - `buildPageUrl()` **从未下发 alpha 参数**；
  - `OverlayService` 全文无任何 `alpha` 应用逻辑（唯一匹配在注释里）。
  - 结果：该字段从头到尾没有任何消费者。
- **修复**：双管齐下
  1. 渲染窗口 `LayoutParams.alpha = overlayAlpha / 100f` —— 窗口级作用于整棵
     View 树，一处生效全局可见，且不与模型自身 alpha 冲突；
  2. 新增 `ACTION_SET_ALPHA`，滑条实时推送；服务侧 `applyWindowAlpha()` 走
     `updateViewLayout`，**不重载页面**（重载会重新加载模型，数秒白屏）。
- **验证**：`dumpsys window windows` 确认渲染窗口 `alpha=0.59`（窗口管理器实际值）。
- **教训**：**新增设置项时，必须验证「写入 → 传输 → 消费」三段是否闭环。**
  只写 SharedPreferences 不等于功能可用 —— 这次错误在 UI 上完全看不出来，
  滑条能动、数值会变，唯独没有效果。
- **附带发现**：用户提到的「还是有点透明」，实际是模型自带 alpha 的观感，
  与该滑条无关（修复前滑条本就没生效）。

### Bug-013 · 拖动几次后失效 + 拖动时模型乱闪（v1.4.0）

- **现象**：①拖动几次后完全拖不动；②拖动过程中模型到处闪/瞬移。
- **根因**：**闭包捕获过期变量**。`syncTouchCatcher()` 里：

  ```kotlin
  created.setOnTouchListener { _, ev ->
      forwardTouchToWebView(ev, x, y, scaleX, scaleY)  // x/y 是函数入参
      true
  }
  ```

  `x`/`y` 是**捕获窗口创建那一刻**的偏移量，被 lambda 闭包固化。
  但捕获窗口在拖动中持续移动（`updateViewLayout`），转发给 WebView 的
  坐标换算却一直用旧偏移：
  - 每次拖动，实际偏移与转发偏移的差值被累积 → 页面收到错误坐标 → **乱闪**；
  - 差值累积到足够大，触摸点落在模型包围盒之外 → 命中判定失败 → **拖不动**。
- **修复**：引入 `@Volatile` 实例字段持有实时几何信息：

  ```kotlin
  @Volatile private var catcherOffsetX = 0
  @Volatile private var catcherScaleX = 1f
  // syncTouchCatcher 末尾发布（夹取修正之后）
  catcherOffsetX = x; catcherScaleX = scaleX
  // 触摸监听器读取当前值而非快照
  forwardTouchToWebView(ev, catcherOffsetX, catcherOffsetY, catcherScaleX, catcherScaleY)
  ```

  同时补充：拖动**过程中**也做边界夹取（原来只在抬手时夹取，
  中途拖出屏幕会导致部分区域无法再命中）。
- **验证**：连续 4 次拖动 **4/4 成功**，窗口位置每次精确左移 234px；
  单次拖动 7 次命中区上报，L 值严格递减无跳变。
- **教训**：
  1. **`setOnTouchListener` / 长生命周期回调里，绝不捕获会变化的外层局部变量。**
     要么用 `@Volatile` 字段，要么用可变持有者。
  2. **捕获窗口与渲染窗口分离的架构下，窗口几何是"活"的** ——
     任何依赖它的换算都必须读当前值。这是两窗口架构的固有约束，
     不是偶发 bug。

### Bug-014 · 日志面板抢占外层滚动（v1.4.0）

- **现象**：主界面滚动到日志区后，无法再滚回上方操作透明度/缩放滑条；
  每次从后台切回，页面都被弹到日志面板。
- **根因**：`refreshLogView()` 无条件执行
  `binding.svLog.fullScroll(FOCUS_DOWN)`。日志区在 `ScrollView` 内，
  内层滚动会**带动外层 ScrollView 一起位移**，导致外层停在日志区。
  而 `onResume` 会调 `refreshLogView()`，所以每次切回都被弹走。
- **修复**：新增 `isLogPanelVisible()`，用 `getGlobalVisibleRect` 判断日志区
  是否**实际可见**（可见高度 ≥ 视图高度的 1/3），只有可见时才自动滚动。
- **教训**：**嵌套 ScrollView 场景下，"自动滚动到底部"必须加可见性前置判定。**
  否则内层滚动会劫持外层视口。`getVisibility()` 在这里无效 —— 滚动到屏幕外
  的 View 依然是 `VISIBLE`，必须用 `getGlobalVisibleRect`。

### Bug-015 · 点击特效坐标变成 NaN（v1.5.0）

- **现象**：真机短按模型，日志显示
  `[JS:FX][D] 点击特效已播放 | x=NaN y=NaN` —— 特效「播放了」但不可见。
- **根因**：`FX.tap(e.clientX, e.clientY)` 读的是事件对象上的坐标。
  但触摸走的是 `touch` 通道，`handleUp()` 以 **`onPointerUp({})`** 调用
  （空对象），抬手事件里根本没有坐标 → `undefined` → `NaN`。
- **修复**：改用 `pointerLastX / pointerLastY`。这两个值在 `onPointerDown`
  时写入、拖拽中持续更新，是抬手时刻真实落点的唯一可靠来源。
- **验证**：点击屏幕 `(1279, 809)` → 日志 `x=568 y=360`，
  与 CSS 视口（1138×664）换算结果完全吻合。
- **教训**：**合成事件的「坐标」字段在不同事件通道下并不可靠。**
  凡是自维护的手势状态（起始点、最后落点）都应显式记录，
  不要依赖 `e.clientX/clientY` —— 尤其是同一处理函数被
  `pointer` / `touch` / `mouse` 三套通道复用的时候。

### 6.4 页面 JS 语法自检

逐个 `<script>` 块抽取后用 `new Function()` 试编译，比 `node --check` 更准确
（能同时覆盖多个 script 块，且不依赖 ES Module 解析）：

```js
const fs = require('fs');
const html = fs.readFileSync('live2d_decor.html', 'utf8');
const re = /<script(?![^>]*\bsrc=)[^>]*>([\s\S]*?)<\/script>/gi;
let m, i = 0, ok = true;
while ((m = re.exec(html))) {
  i++;
  try { new Function(m[1]); console.log('script#' + i + ' OK'); }
  catch (e) { ok = false; console.log('script#' + i + ' FAIL: ' + e.message); }
}
console.log(ok ? 'ALL PASS' : 'HAS ERROR');
```

### 6.5 触摸事件注入（自动化测试用）

**单指手势**可用 `input motionevent` 精确控制按下/移动/抬起时序，
这是验证「长按解锁 → 拖拽 → 松手吸附」全链路的关键：

```bash
ADB=C:/Android/Sdk/platform-tools/adb.exe
# 1) 先读捕获窗口位置（它随模型移动，每次测试前都要重读）
"$ADB" shell dumpsys window windows | grep -oE '\([0-9]+,[0-9]+\)\(406x[0-9]+\)' | head -1
# 2) 在窗口中心按下 → 停留 >400ms 触发长按解锁 → 移动 → 抬起
"$ADB" shell input motionevent DOWN 1279 809; sleep 0.6
"$ADB" shell input motionevent MOVE 1100 809; sleep 0.2
"$ADB" shell input motionevent UP   1100 809
```

> ⚠️ **多点触控（双指）无法用 adb 注入** —— 本机已验证两条路径均不可行：
> - `sendevent /dev/input/eventN` → `Permission denied`
>   （节点属 `root:input`；`adb root` 在 production build 被拒，且无 `su`）
> - `input motionevent` 只有 `DOWN|UP|MOVE|CANCEL`，**无 POINTER_DOWN**；
>   连发两次 `DOWN` 会被框架拆成两个独立单指手势（日志可证第二指不产生 `pointerCount=2`）
>
> 结论：**pinch 类功能只能人工验证**，或在 debug 构建里加一条仅测试用的注入入口。

## 七、已知限制

1. **模型版权水印**：本模型的水印是参数层，可关闭。但若换成把版权信息
   烘焙进主纹理的模型，则无法通过参数去除。
2. **VTS 热键不可用**：`miku.vtube.json` 中的 `Hotkeys` 是 VTS 私有机制，
   本 App 无法读取或执行。
3. **模型动作需逐个逆向**：换新模型时，`MODEL_ACTIONS` 动作库需要
   重新解析该模型的 `cdi3.json` + `exp3.json` 才能适配。
4. **触摸热区精度**：命中判定用几何近似（忽略模型旋转的微小平移），
   在模型大幅旋转时可能有 ±6px 误差。
5. **调试通道未设防**：`ACTION_DEBUG_JS` 可注入任意 JS，仅适合 debug 构建，
   正式发布前建议加 `BuildConfig.DEBUG` 判定。
6. **多指手势无法自动化验证**（v1.5.0 起）：production build 无 root，
   `sendevent` 与 `input motionevent` 两条注入路径均不可用。
   双指缩放等手势类功能只能人工确认，或在 debug 构建里加仅测试用的注入入口。
7. **边缘吸附只覆盖水平方向**：这是刻意的设计取舍（见 v1.5.0 更新日志），
   若后续希望模型能停靠屏幕顶部/底部，需要额外设计垂直吸附策略。
