## 一、这是什么

一个 Android 应用，在系统桌面上叠加一层 **Live2D 模型**，并实现**区域化触摸**：

- **模型范围内** —— 可点击（播放动作 + 点击特效）、可长按（解锁拖拽 + 抓住脉冲）、可拖拽移动、双指捏合缩放、视线跟随手指；
- **模型范围外** —— 触摸**完全穿透**到桌面，不干扰任何正常操作。

**当前版本**：`v1.5.0`（`versionCode = 6`）｜**包名**：`com.live2d.overlay`
**验证机型**：小米平板（Android 15，横屏 2560×1494）
**产出**：[`../artifacts/Live2DOverlay-v1.5.0.apk`](../artifacts/Live2DOverlay-v1.5.0.apk)

技术路线来自对 **MikuCarLauncher** 的逆向还原（见 [`40_逆向分析_MikuCarLauncher.md`](40_逆向分析_MikuCarLauncher.md)），
悬浮窗叠加方式经**氢桌面「悬浮地图」机制**验证可行（见 [`42_氢桌面悬浮窗可行性验证.md`](42_氢桌面悬浮窗可行性验证.md)）。

> `Your project path contains non-ASCII characters.` 本工作区路径是
> `D:\AI Dsh\车机项目\Live2D悬浮窗\src\Live2DOverlay`（含中文），

> **若换机器构建失败，先怀疑这一条**；更稳的做法是把工程放到纯 ASCII 路径（如 `D:\AtzGauge\Live2DOverlay`）。


## 四、系统架构

### 4.1 两窗口分离（核心设计）

| 窗口 | 尺寸位置 | 触摸标志 | 职责 |
|---|---|---|---|
| **渲染层** | 全屏 MATCH_PARENT | 含 `FLAG_NOT_TOUCHABLE` | 只负责画（WebView + WebGL） |
| **捕获层** | 恰好等于模型包围盒 | **不含** `NOT_TOUCHABLE` | 只负责收触摸，转发给渲染层 |

交互区域之外**从来不属于任何窗口**，触摸天然落到桌面，无需任何时序博弈。

> ★ **已被证伪、不要再尝试的方案**：单窗口「常驻可触摸 + `dispatchTouchEvent` 判断落点后翻转 `FLAG_NOT_TOUCHABLE`」。
> 根因：Android 输入管线在 `ACTION_DOWN` 派发时就把**整个手势序列绑定**给了目标窗口，
> 事后摘除标志不会让已注入的 DOWN 重新路由。已实测证伪（80ms / 220ms 两种挂起时长均失败）。

### 4.2 数据流

```
用户手指
  ↓ 捕获层 View.onTouchEvent
  ├─ handlePinch()        → 双指？→ 原生算缩放 → evaluateJavascript(__mikuLive2DSetUserScale)
  └─ forwardTouchToWebView() → 构造单点 MotionEvent 注入渲染层 WebView
        ↓ 页面 pointer/touch 事件
        ├─ isOpaqueAt(x,y)  纯 CPU 几何命中判定（绝不读帧缓冲）
        ├─ 点击 → FX.tap() + playModelAction()
        ├─ 长按 → 解锁拖拽 + 抓住脉冲
        └─ 拖拽 → 改 model.x/y → reportHitArea()
              ↓ Live2DJSBridge（JS → Java）
              └─ syncTouchCatcher()  → 重设捕获窗口位置/尺寸
```

### 4.3 坐标系（最容易出错的地方）

| 坐标系 | 尺寸（实测） | 来源 |
|---|---|---|
| View 像素 | 2560 × 1494 | `MotionEvent.getX/Y`、`dispatchTouchEvent` |
| CSS 像素 | 1138 × 664 | 页面 `window.innerWidth/Height` |

**相差约 2.25 倍**（devicePixelRatio 缩放）。换算由页面上报 `vw/vh`，Android 侧按
`cssX = viewX * (vw / viewW)` 处理。**直接比较两者必然失败。**

## 五、六条不可违背的架构约束

这六条是 16 个 Bug 换来的，改动前务必确认没有违反：

1. **命中判定必须纯 CPU 几何** —— 调 `app.renderer.render(stage, viewport)` 会改写主帧缓冲，
   恢复 `stage.x/y` 无效 → 用户看到「点击闪色」（Bug-001）。
2. **Live2D 参数覆盖必须挂 `beforeModelUpdate`** —— 渲染链路是
   `ticker 回调 → internalModel.update()（参数求值）→ 渲染`，在 ticker 里 set 会被覆盖（Bug-003）。
3. **位置所有权必须唯一** —— `updateDefaultIdle()` 每帧覆写 `model.x/y` 会与拖拽打架，
   必须靠 `manualPositioned` / `touchManaged` 状态互斥（Bug-002）。
4. **长生命周期回调里禁止捕获会变化的局部变量** —— `setOnTouchListener` 等回调必须读
   `@Volatile` 字段，而不是闭包捕获的入参（Bug-013）。
5. **带进行中状态的开关，关闭时必须收尾** —— 凡是在 ticker 里每帧改写模型属性的状态变量
   （吸附补间、缩放脉冲），关开关时必须一并清除，否则动画会继续跑。
6. **窗口的创建与销毁必须成对，`detachOverlay()` 要移除全部窗口** ——
   `TYPE_APPLICATION_OVERLAY` 窗口**不随 Service 停止而消失**（进程仍存活时窗口照旧在屏）。
   只移除渲染窗口会泄漏捕获窗口，残留窗口仍可触摸但回调指向已销毁的旧实例，
   表现为「拖几次就拖不动」（Bug-016，实测 3 轮启停泄漏 5 个窗口）。

> **另有两条平台事实（不是本项目的设计选择，改代码解决不了）**：
> - **全屏穿透式悬浮窗的不透明度硬上限是 0.8** —— Android 12+ 对带 `FLAG_NOT_TOUCHABLE`
>   的系统悬浮窗强制压低 alpha；应用层无法指定触摸区域（本机 `WindowManager.LayoutParams`
>   没有 `touchableRegion` 成员），`maximum_obscuring_opacity_for_touch` 在本机也不生效。
>   **不要再去尝试突破它**（两条路径都已实测证伪）。
> - **`ACTION_DEBUG_JS` 当前无设防**，可注入任意 JS（见迭代清单 P0-4）。

> 另有两条衍生规则：
> - **新增设置项必须验证「写入 → 传输 → 消费」三段闭环**，只写 `SharedPreferences` 不等于功能可用（Bug-012）。
> - **不要假设参数正负语义**，必须实测（水印 `Param137` 就是反向语义：`1` = 隐藏）。

## 六、真机验证能力与边界

### 6.1 单指手势 —— 可用 adb 精确注入

```bash
ADB=C:/Android/Sdk/platform-tools/adb.exe
# ① 每次测试前重读捕获窗口位置（它随模型移动，固定坐标会失效）
"$ADB" shell dumpsys window windows | grep -oE '\([0-9]+,[0-9]+\)\(406x[0-9]+\)' | head -1
# ② 按下 → 停留 >400ms 触发长按解锁 → 移动 → 抬起
"$ADB" shell input motionevent DOWN 1279 809; sleep 0.6
"$ADB" shell input motionevent MOVE 1100 809; sleep 0.2
"$ADB" shell input motionevent UP   1100 809
```

### 6.2 多点触控 —— **无法注入，只能人工验证**

设备为 production build，两条路径均封死（已实测）：

| 路径 | 结果 |
|---|---|
| `sendevent /dev/input/eventN` | `Permission denied`（节点属 `root:input`；`adb root` 报 "cannot run as root in production builds"，无 `su`） |
| `input motionevent` | 只支持 `DOWN\|UP\|MOVE\|CANCEL`，**无 POINTER_DOWN**；连发两次 `DOWN` 被拆成两个独立单指手势 |

→ **pinch 类功能请直接标记「需人工验证」并告知用户，不要在上面反复尝试。**

### 6.3 服务未 exported —— 只能走 App 界面

`am startservice` / `am start-foreground-service` 报 `Requires permission not exported`。
调试只能通过 UI 开关拉起服务，方法是 `uiautomator dump` 取坐标 + `input tap`。

> 已知限制：MIUI 的 `uiautomator dump` 会**截断**节点树（约 12KB 后停止），
> 开关类控件可能需要先滚动到可视区才会出现在 dump 里。

### 6.4 设备锁屏会让一切 UI 自动化失效

`uiautomator dump` 只 dump 到 `com.android.systemui` 的 keyguard 节点 = 设备锁着。
`input keyevent 224` 可唤醒，但**带 PIN 的锁屏无法用 adb 绕过**，只能请用户手动解锁。
受保护广播（如 `BOOT_COMPLETED`）shell 无权发送，不要试图用广播自救。

### 6.5 日志是主要排查手段

应用内置结构化日志（`L2DLog`），统一格式：

```
[HH:mm:ss.SSS][MODULE][LEVEL] message | k=v k=v
```

- 级别：`V/D/I/W/E`（界面可过滤，**持久化到 SharedPreferences**）
- 模块：`SVC/CFG/BRIDGE/UI/RENDER/TOUCH/MOTION/PARAM/WM/FX`
- 环形缓冲 800 条 + 落盘滚动 3 天 + 文本/JSON 一键导出

实时观察（logcat 镜像默认开启）：

```bash
"$ADB" logcat -c && "$ADB" logcat -d -s L2DLog | grep -E 'TOUCH|MOTION|FX'
```
