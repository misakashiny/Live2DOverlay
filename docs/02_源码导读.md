**`handlePinch` 的四个必踩的坑**（都已修好，改动时别破坏）：

1. **第二指落下时必须先 `__mikuLive2DCancelPointer()`** —— 第一指往往已让页面进入 dragging，
   不撤销就变成「页面一边跟手指改 `model.x`、一边被缩放」→ 一边放大一边乱飘。
2. **手势结束必须把 `pinchActive` 归位**（`POINTER_UP` / `UP` / `CANCEL` 三处都要），
   否则下一轮单指操作全被判成缩放 → 缩放一次之后拖动失灵。
3. **`ACTION_POINTER_UP` 时 `pointerCount` 仍包含刚抬起的那根手指**，
   所以判断条件是 `<= 2` 而不是 `< 2`。
4. **`ACTION_UP` 且 `pinchActive` 时必须 `return true` 消费掉**，
   否则页面把这次抬起当一次点击，白播一次动作 + 一次特效。

**服务动作常量**：

| 常量 | 用途 |
|---|---|
| `ACTION_START` / `ACTION_STOP` | 启动 / 停止 |
| `ACTION_REFRESH` | 重载页面（会重新加载模型，数秒白屏，**慎用**） |
| `ACTION_SET_TOUCHABLE` | 切换触摸模式（不重载） |
| `ACTION_SET_ALPHA` | 调透明度（不重载） |
| `ACTION_DEBUG_JS` | 注入任意 JS（**当前无设防，见迭代清单 P0-4**） |

**两个易错点**：

- `LOG_LEVEL_ALL = "ALL"` 是「全部」这一项的**哨兵值** —— 它不是任何 `Level`，
  所以 `L2DLog.minLevel` 是 `Level?`。改动级别逻辑时别把 `null` 当成异常。
- 日志区行号计算依赖 `logLastTouchY`（由 `setOnTouchListener` 记录）。
  `OnLongClickListener` **必须 `return false`**，否则会吃掉事件、原生选词菜单失效。

### 2.4 `OverlayConfig.kt`（201 行）—— 配置与 URL 协议

SharedPreferences 单一数据源，路径 `shared_prefs/live2d_overlay_prefs.xml`。

| 分组 | 键 |
|---|---|
| 基础 | `enabled` / `model_path` / `auto_start` |
| 显示 | `center_x` / `center_y` / `scale` / `quality` / `fps` / `clip_bottom` / `clip_enabled` / `design_w` / `design_h` / `overlay_alpha` |
| 交互 | `touch_enabled` / `hide_watermark` |
| **v1.5.0** | `action_cycle` / `tap_effect` / `edge_snap` / `log_min_level` |

**`buildPageUrl()` 下发的完整参数**：

```
live2d_decor.html?model=<file://...>&dw=&dh=&cx=&cy=&scale=&quality=&fps=
                 &clip=&clipBottom=&touch=1&autoPos=1&watermark=1&cycle=0&fx=1&snap=1
```

> ★ **触摸模式下不下发 `cx/cy`，改发 `autoPos=1`** —— 触摸时位置由用户拖拽决定，
> 设置页滑条不再参与定位（否则会出现「设了坐标但拖一下就失效」的困惑）。

> ★ **三个 v1.5.0 参数在页面侧用 `let` 而非 `const` 接收** —— 为了 Android 侧能运行时热切换。

## 四、双向接口契约速查

```
Android → 页面      evaluateJavascript("window.__mikuLive2DXxx && window.__mikuLive2DXxx(...)")
页面 → Android      window.MikuLive2DAndroid.xxx(...)      ← 名字必须逐字一致
```

| 通道 | Android 常量 | 是否重载页面 |
|---|---|---|
| 切触摸模式 | `ACTION_SET_TOUCHABLE` | 否 |
| 调透明度 | `ACTION_SET_ALPHA` | 否 |
| **热切换开关**（`cycle`/`fx`/`snap`） | **`ACTION_SET_PAGE_OPTION`**（v1.7.1 起，只收白名单 key） | 否 |
| **播关键帧动画**（`id` 或 `slot`） | **`ACTION_PLAY_ANIMATION`**（v1.7.2） | 否 |
| **重推人设** | **`ACTION_REPUSH_PERSONA`**（v1.7.2） | 否 |
| 改坐标/缩放/画质/**Soullink 开关** | `ACTION_REFRESH` | **是（数秒白屏）** |
| ~~注入任意 JS~~ | `ACTION_DEBUG_JS` | ⚠️ **仅 debug 构建可用**（v1.7.1 P0-4）。**正式功能不要再借道它** |

| `__mikuLive2DApplyProfile(json)` | 装载模型档案（动作 + 动画 + 水印参数） |

| `__mikuLive2DPlayPersonaSlot(slot)` | 按人设语义槽位随机播（`onTap` / `onIdle` / …） |
| `__mikuLive2DStopAnimation(id?)` | 停指定 / 全部动画 |
| `__mikuLive2DListAnimations()` | 列出可用动画 id |
| `__mikuLive2DApplyPersona(json)` | 装载角色人设 |
| `__mikuLive2DGetPersona()` | 读当前人设 id |
| `__mikuLive2DStartSoullink(profile)` | ★ 注入档案并启动 Soullink 引擎 |
| `__mikuLive2DSoullinkMessage(text)` | ★ 向引擎投递消息（后续情绪引擎用） |
| `__mikuLive2DSoullinkStatus()` | ★ 返回 `{enabled, ready, frames}` |

### 档案注入为什么都走「原生读文件 + evaluateJavascript」

页面以 `file:///android_asset/` 加载，**对同目录 JSON 发 `fetch`/XHR 会受 file:// 同源策略限制**，
各 ROM 行为不一致（Soullink 的 `loadModelProfile()` 就是这么挂的，真机报 `unknown scheme`）。
→ 统一由 Kotlin 读文件后注入。见 `pushModelProfileToPage()` / `pushPersonaToPage()` / `pushSoullinkToPage()`。

## 六、页面 JS 语法自检（改完必跑）

逐个 `<script>` 块抽取后用 `new Function()` 试编译 —— 比 `node --check` 更准确
（能覆盖多个 script 块，且不依赖 ES Module 解析）：

```js
const fs = require('fs');
const html = fs.readFileSync('app/src/main/assets/live2d/live2d_decor.html', 'utf8');
const re = /<script(?![^>]*\bsrc=)[^>]*>([\s\S]*?)<\/script>/gi;
let m, i = 0, ok = true;
while ((m = re.exec(html))) {
  i++;
  try { new Function(m[1]); console.log('script#' + i + ' OK'); }
  catch (e) { ok = false; console.log('script#' + i + ' FAIL: ' + e.message); }
}
console.log(ok ? 'ALL PASS' : 'HAS ERROR');
```
