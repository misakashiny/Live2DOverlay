## 一、已建成的骨架（本轮交付）

```
┌──────────────────────────────────────────────────────────────┐
│ MainActivity                                                  │
│   角色人设面板：tv_persona / btn_persona_pick / btn_anim_test  │
└───────────────────────┬──────────────────────────────────────┘
                        │ ACTION_REPUSH_PERSONA / ACTION_PLAY_ANIMATION
┌───────────────────────▼──────────────────────────────────────┐
│ OverlayService                                                │
│   loadModelProfileJson()  → 档案（动作 + 动画 + 水印参数）      │
│   PersonaStore.load()     → 人设                              │
│   onPageFinished: 先 pushModelProfileToPage()                 │
│                   再 pushPersonaToPage()  ← 顺序不能反         │
└───────────────────────┬──────────────────────────────────────┘
                        │ evaluateJavascript
┌───────────────────────▼──────────────────────────────────────┐
│ live2d_decor.html                                             │
│   __mikuLive2DApplyProfile()  → MODEL_ACTIONS + ANIMATIONS     │
│   __mikuLive2DApplyPersona()  → activePersona（语义槽位）      │
│   __mikuLive2DPlayAnimation(id) / PlayPersonaSlot(slot)        │
│   installAnimationTicker()  ← 挂 beforeModelUpdate            │
└──────────────────────────────────────────────────────────────┘
```

**为什么人设必须在档案之后推送**：人设里的 `animations` 槽位引用的是
`model-profile.json` 里的动画 id。档案先落地，页面才知道有哪些动画可用。

## 二、角色动画的制作（关键交付）

### 2.1 从「离散姿态」到「关键帧曲线」

v1 的 `actions` 只能表达「把某参数设成某值、持续 N 毫秒」——是离散姿态，
做不出点头、摇摆这类连续动作。v2 的 `animations` 补上这一层：

```jsonc
{
  "id": "nod",                 // 唯一 id，人设用这个引用
  "name": "点头",              // 给人看的
  "kind": "oneshot",           // oneshot = 播一次；loop = 循环
  "durationMs": 1100,
  "tracks": [
    { "param": "ParamAngleY",
      "keys": [[0, 0], [0.30, -14], [0.62, 6], [1, 0]] }   // [归一化时间 0~1, 参数值]
  ]
}
```

- `keys` 由页面**线性插值**采样，时间归一化到 0~1
- `oneshot` 播完把该轨道参数**归零**（否则模型卡在最后一帧）
- `loop` 循环；同名 loop 重复播放是**幂等**的（不会越叠越快）

### 2.2 ★ 制作动画时的两条铁律

| 铁律 | 原因 |
|---|---|
| **关键帧写入必须挂 `beforeModelUpdate`** | 渲染链路是 `ticker → internalModel.update()（参数求值）→ 渲染`。挂 ticker 会被求值覆盖（Bug-003 同源）。页面已用 `installAnimationTicker()` 实现，**不要在 ticker 里 setParam** |
| **关键帧动画用连续参数，`actions` 用离散参数** | 前者走 `ParamAngleX/Y/Z`、`ParamBreath`、`ParamEye*` 等；后者走 `Param125/130/131/132/133/134/135/136`。两者互不干扰，可叠加 |

### 2.3 内置动画清单（`model-profile.json`）

| id | 名称 | 类型 | 时长 | 主要参数 |
|---|---|---|---:|---|
| `nod` | 点头 | oneshot | 1100ms | `ParamAngleY` / `ParamAngleZ` |
| `smile` | 微笑 | oneshot | 1400ms | `ParamEyeSmile` / `ParamMouthForm` |
| `surprise` | 惊讶 | oneshot | 900ms | `ParamEyeLOpen/ROpen` / `ParamMouthOpenY` |
| `blush` | 脸红 | oneshot | 2200ms | `Param130` / `ParamAngleZ` |
| `lean_forward` | 前倾 | oneshot | 1600ms | `ParamBodyAngleX` / `ParamAngleY` |
| `idle_sway` | 待机摆动 | loop | 4600ms | `ParamAngleX` / `ParamAngleZ` |
| `idle_breathe` | 待机呼吸 | loop | 3400ms | `ParamBreath` / `ParamBustY` |

> **换模型时**：`ParamAngle*` / `ParamBreath` / `ParamEye*` 是 Cubism 标准参数，
> 多数模型都有；`Param130/125/13x` 是本模型私有的离散动作参数，换模型必须重新逆向
> （用 `__mikuLive2DDumpParam` / `__mikuLive2DAuditWatermark` 配合 `cdi3.json`）。

## 三、角色人设（AI 角色系统 P1）

### 3.1 文件与优先级

| 优先级 | 路径 | 用途 |
|---|---|---|
| 1 | `/sdcard/Live2DModels/<id>/persona.json` | 随模型走，**可热改**（改完重开悬浮窗） |
| 2 | `assets/personas/<id>.json` | 内置，保证开箱可用 |

- 结构约束：[`assets/persona-schema.json`](../src/Live2DOverlay/app/src/main/assets/persona-schema.json)
- 校验实现：`PersonaStore.validate()` —— **是那份 Schema 的等价实现，改一处必须同步改另一处**
- 为什么不用 JSON Schema 库：Android 上加依赖（体积 + 混淆规则）不划算，
  而本结构只有十几个字段，手写校验错误提示更贴中文语境

### 3.2 人设如何连到动画

人设**只写动画 id**，不写参数 —— 动画本体在 `model-profile.json`，
这样同一套动画可被多个人设复用：

```jsonc
"animations": {
  "onTap":           ["nod", "smile"],
  "onLongPressDrag": ["surprise"],
  "onIdle":          ["idle_sway"],          // 装载后自动起循环
  "onEmotion": {
    "joy_high":     ["smile", "nod"],        // P2 情绪引擎消费
    "shyness_high": ["blush"],
    "anger_high":   ["lean_forward"]
  }
}
```

**已接通的槽位**：`onIdle`（装载时自动起）、`onTap`（点击优先走它，
失败回落原 actions 路径）。`onEmotion` 已定义但**尚无消费者**——留给 P2。

## 四、接口契约（P2/P4 直接接这里）

### 4.1 Android → 页面

| 接口 | 用途 | 引入 |
|---|---|---|
| `__mikuLive2DApplyProfile(json)` | 装载模型档案（动作 + 动画 + 水印参数） | v1.7.0 / v1.7.2 |
| `__mikuLive2DApplyPersona(json)` | 装载人设 | **v1.7.2** |
| `__mikuLive2DPlayAnimation(id)` | 播指定动画 | **v1.7.2** |
| `__mikuLive2DPlayPersonaSlot(slot)` | 按人设语义槽位随机播 | **v1.7.2** |
| `__mikuLive2DStopAnimation(id?)` | 停指定/全部动画 | **v1.7.2** |
| `__mikuLive2DListAnimations()` | 列出可用动画 id | **v1.7.2** |
| `__mikuLive2DGetPersona()` | 读当前人设 id | **v1.7.2** |

### 4.2 Service Action（正式通道，**不受 debug 守卫影响**）

| Action | extra | 用途 |
|---|---|---|
| `ACTION_SET_PAGE_OPTION` | `key` / `on` | 三个热切换开关（白名单） |
| `ACTION_PLAY_ANIMATION` | `id` 或 `slot` | 播动画（id 限 `[A-Za-z0-9_-]`） |
| `ACTION_REPUSH_PERSONA` | — | 切角色后重推人设，**不重载页面** |

> `ACTION_DEBUG_JS` 仅 debug 构建可用（v1.7.1 P0-4）。**正式功能不要再借道它。**

## 五、日志模块

`L2DLog.Mod` 现为 **11 个**：`SVC / CFG / BRIDGE / UI / RENDER / TOUCH / MOTION / PARAM / WM / FX / AI`

> ⚠️ v1.7.2 修正：v1.5.0 文档写「模块表加 FX」，但当时**只加了页面侧的 `M.FX`**，
> Kotlin 侧一直缺这一项（页面经桥上报 "FX" 仍能工作，因为 `writeFromJs` 只拼 "JS:" 前缀、
> 不查枚举）。本轮补齐 `FX` 并新增 `AI`。
> **新增模块时两侧都要加**（`L2DLog.Mod` 与页面 `M`），否则界面按模块过滤会漏。

## 六、下一步（P2 情绪引擎）的接入点

已就绪、P2 可直接用的东西：

| 已有 | P2 怎么用 |
|---|---|
| `PersonaStore.Persona.emotionBias` | 情绪基线偏置（**偏置，不是绝对值**） |
| `PersonaStore.Persona.traits` | 约束 LLM 与情绪基线 |
| `emotionPhysics.decayRatePerSec` / `maxDeltaPerSec` | 衰减与限速（**必须本地**，否则断网就僵住） |
| 人设 `animations.onEmotion` | 情绪 → 动画 id 的映射表 |
| `ACTION_PLAY_ANIMATION` | 情绪引擎播动画的出口 |
| `L2DLog.Mod.AI` | 记录情绪变化、降级事件 |

**P2 只需新增**：`EmotionEngine`（6 维值 + 衰减 + 触发）、`EmotionArbiter`（乱序保护 +
权重融合 + 变化率限制）、`EmotionToActionMapper`。**不需要改任何现有格式。**
