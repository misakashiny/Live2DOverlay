## 四、真机安装与崩溃修复（01:30）

### 设备

### ★ 真机发现致命 bug：无限递归 StackOverflowError
**症状**：首次启动即被系统提示「Live2D 桌面因自身问题闪退」。
logcat `-b crash` 显示 `java.lang.StackOverflowError`，堆栈为
`onResume → refreshState → requestNotification.launch → 回调 → refreshState → ...`

**根因**：`refreshState()` 末尾写了
```kotlin
if (!notifOk && SDK_INT >= TIRAMISU) requestNotification.launch(POST_NOTIFICATIONS)
```
而 `requestNotification` 的回调里又调用 `refreshState()`，形成闭环。每次 launch 都会立即回调（已拒绝时），瞬间耗尽栈。

**修复**：
1. 从 `refreshState()` 中**彻底移除**所有权限申请调用；
2. 新增独立方法 `maybeRequestNotification()`，用 `notificationRequested` 布尔标志保证**单次生命周期只申请一次**；
3. 只在 `onCreate` / `onResume` 调用 `maybeRequestNotification()`。

**教训（通用）**：`registerForActivityResult` 的回调中**绝不能**调用会再次触发同一 launcher 的方法。
凡「状态刷新」与「权限申请」耦合，就是递归隐患。刷新只读状态，申请单独走一次性入口。

### 顺带修复：startService 用于前台服务
`stopOverlay()` / `pushLiveUpdate()` 里用 `startService()` 启动一个已是前台服务的 Service，
在 Android 8+ 会抛 `IllegalStateException`（后台启动限制）。
→ 统一抽成 `safeStartService()`，内部优先 `ContextCompat.startForegroundService` 并带 fallback。
同时 `intent.action = X` 全部改为 `setAction(X)`（Kotlin 会解析到 getter 导致 `val cannot be reassigned`）。

### 真机权限事实（MIUI）
- **悬浮窗权限走 `appops`，不走运行时权限**：
  `dumpsys package` 里 `SYSTEM_ALERT_WINDOW: granted=false`，
  但 `appops get <pkg> SYSTEM_ALERT_WINDOW` 为 `allow`，`Settings.canDrawOverlays()` 读 appops → 返回 true。
  **排查悬浮窗权限必须用 `appops`，看 dumpsys 会误判**。
- `pm clear <pkg>` 会**同时重置 appops 状态**（悬浮窗权限一并丢失），重置后需重新授权。
- 两种授权命令：
  ```bash
  adb shell appops set <pkg> SYSTEM_ALERT_WINDOW allow
  adb shell pm grant <pkg> android.permission.POST_NOTIFICATIONS
  ```
- 通知权限弹窗若点弹窗外侧取消，权限记为 denied，且 `flags=[USER_SENSITIVE_WHEN_GRANTED|USER_SENSITIVE_WHEN_DENIED]`，
  之后 `pm grant` 仍可强制授予。

### ★★ 触摸交互：两窗口架构（本阶段最大技术突破）

**问题**：悬浮窗是全屏的。整窗可触摸会吃掉整个桌面；整窗 NOT_TOUCHABLE 又无法接收模型上的触摸。

**被证伪的方案（务必不要再试）**：
「窗口常驻可触摸 + 在 dispatchTouchEvent 里判断落点，落点在外就返回 false 并翻转
FLAG_NOT_TOUCHABLE」——**实测无效**。Android 的输入管线在 ACTION_DOWN 派发时就把
整个手势序列**绑定**给了目标窗口；事后摘除 NOT_TOUCHABLE 不会让已注入的 DOWN
重新路由到下层。表现为「点了桌面图标没反应」。
（试过 80ms / 220ms 两种挂起时长，均失败。WindowManager 还会因检测到
FLAG_NOT_TOUCHABLE 而强制把 alpha 压到 0.80。）

**正确方案：渲染窗口与触摸窗口分离**
- **Window A（渲染层）**：全屏 MATCH_PARENT，**永久 `FLAG_NOT_TOUCHABLE`**，只负责画。
- **Window B（触摸捕获层）**：尺寸/位置**恰好等于模型包围盒**，可触摸。

其余区域从来不属于任何窗口 → 触摸天然落到桌面，**无需任何时序博弈**。

关键实现：
```kotlin
// Window B 的事件转发到渲染层 WebView（构造新 MotionEvent 注入）
val converted = MotionEvent.obtain(
    ev.downTime, ev.eventTime, ev.action,
    ev.x + offsetX, ev.y + offsetY,   // 捕获窗口内坐标 → 屏幕坐标
    ev.metaState
)
webView.dispatchTouchEvent(converted)
```

dumpsys 铁证：
```
Window #9  (345x834) @(1589,384)  fl=NOT_FOCUSABLE LAYOUT_IN_SCREEN ... HARDWARE_ACCELERATED   ← 捕获层，可触摸
Window #10 (fillxfill) @(0,0)     fl=NOT_FOCUSABLE NOT_TOUCHABLE LAYOUT_IN_SCREEN ...          ← 渲染层，穿透
```

### ★ 坐标系陷阱（第二隐蔽的坑）
**`dispatchTouchEvent` 的 `e.x/e.y` 是 View 像素（2560×1494），
而页面的 `window.innerWidth` 是 CSS 像素（1138×664）** —— Android WebView 按
devicePixelRatio 缩放。两者相差约 2.25 倍，直接比较必然失败。
→ 页面必须把 `vw/vh` 随包围盒一起上报，Android 侧按 `cssX = viewX * (vw/viewW)` 换算。

### 其他实现细节
- **边界粘滞**：`touchSequenceActive + sequenceStartedInside` 双状态。
  只在「手指已按下且起始点在模型内」时启用粘滞，避免一次命中后
  数百毫秒内所有落点都判为命中（会出现「桌面点不动」的假象）。
  第一版用纯时间窗口（`now - lastHitAt < 400ms`）就是这个 bug。
- **像素级命中**：`isOpaqueAt()` 把模型渲染到 96×96 离屏画布读 alpha，
  过滤掉模型四周的透明留白。渲染不可用时退化为矩形判定。
- **`touchEnabled` 必须从 `config` 读取**：初版字段默认 `true` 且从不读配置，
  导致关闭「触摸交互」后 `onHitAreaChanged` 仍重建捕获窗口，纯穿透模式失效。
- **页面事件兼容**：Android WebView 对合成 MotionEvent 倾向派发 `touch` 系列而非
  `pointer`，两套都接。CSS 需 `touch-action: none`，否则拖拽变页面滚动。
- **拖拽期间禁止待机逻辑改写位置**：`updateDefaultIdle()` 里加 `if (!dragging)` 守卫，
  否则「拖着拖着弹回去」。

  手动置 1 后截图比对。审计显示加载后 Param137 默认值就是 0。

### ★ 第二条重要发现：参数覆盖必须挂 beforeModelUpdate，不能挂 ticker

渲染链路：`app.ticker 回调 → internalModel.update()（参数求值）→ 渲染`。
在 ticker 里 setParam 会被随后的 update 覆盖。
正确时机：`model.internalModel.on("beforeModelUpdate", ...)`。
这是上一轮「水印关闭不生效」的真正根因（叠加反向语义，双重错误）。

### ★ 第三条：R5「浮空」的真相 = 水印 Mesh 撑大包围盒

**没有「让人站起来」的开关**。所谓浮空/模型小/发虚，主因是水印文字 Mesh
撑大了 `getBounds()` → `targetModelHeightPx / rawModelHeight` 算出的缩放偏小。
水印隐藏后模型立即恢复正常大小位置。次要成因是 Scene1 待机动作的位移。

### R1 点击闪色根因（重要架构教训）

`isOpaqueAt()` 里调 `app.renderer.render(stage, viewport)` 会把整个舞台渲染
到**主画布**，`drawImage` 采样后主帧缓冲已被改写，恢复 stage.x/y 也救不回来
→ 每帧点按都闪一下。

**修复**：彻底放弃 GPU 采样，改纯 CPU 几何判定（两级：屏幕包围盒粗筛 →
反变换到模型局部坐标细筛）。**任何为「辅助计算」而调主渲染器 render() 的做法
都是危险的**。

### R2 无法拖动根因

`updateDefaultIdle()` 每帧无条件 `model.x = centerX * stageScaleX() + extraX`，
与拖拽互相打架。修复：引入 `manualPositioned` / `touchManaged` 双状态，
置位后待机逻辑不再覆写坐标；`OverlayConfig` 在触摸模式**不下发 cx/cy**，
改发 `autoPos=1`；自动模式初始落点 = 屏幕水平居中 + 垂直 62%。

**教训：位置所有权必须唯一**，多来源同写 model.x/y 必然打架。

## 九、v1.5.0 · 交互增强 + 日志增强

### 已实现
1. **点击特效**：独立 `#fx` DOM 层 + CSS 动画（涟漪 + 6 道星光）。

3. **边缘吸附**：松手时距左右边缘 < 14% 视宽 + 半宽 触发，easeOutCubic 补间。
   **只吸附水平方向**（垂直强塞顶/底违背直觉）。新按下必须 `cancelEdgeSnap()`。
4. **动作轮播**：`playModelAction()` 按开关分派随机/轮播。
5. **双指缩放**：见下方新踩坑。
6. **日志三项**：级别持久化（哨兵 `"ALL"`）、JSON 导出、长按复制单条。

### ★ 新踩坑（跨版本通用）
1. **双指手势必须在原生捕获层识别**：`forwardTouchToWebView()` 只取 `ev.x/ev.y`
   构造**单点** MotionEvent，页面永远收不到第二根手指，页面内无法识别 pinch。
   → 原生算好缩放值，页面只留 `__mikuLive2DSetUserScale(s)` 落地接口。
2. **pinch 开始时必须撤销页面的单指拖拽**（`__mikuLive2DCancelPointer()`），
   否则页面一边跟手指改 `model.x`、一边被缩放 → 「一边放大一边乱飘」。
3. **带进行中状态的功能，关闭开关时必须收尾**：关 `snap` 要 `cancelEdgeSnap()`，
   否则补间继续把模型拽向边缘。与「位置所有权唯一」是同类问题。
4. **`OnLongClickListener` 返回 false 才能与原生长按选词并存**（返回 true 会消费掉）。
   行号计算要另配一个 `setOnTouchListener`（同样返回 false）记录 `ev.y`。
5. **界面「全部」这类无对应枚举值的选项，要用哨兵值存档**；
   为此把 `L2DLog.minLevel` 从 `Level` 改成 `Level?`。
6. **设备会锁屏**：`adb shell am broadcast -a android.intent.action.BOOT_COMPLETED`
   属于受保护广播，shell 无权发送（报 SecurityException）—— 拉不起服务。
   真机验证前先 `input keyevent 224` 唤醒并确认 `uiautomator dump` 能看到 App 界面。

### ★ Bug-015：点击特效坐标 NaN
`FX.tap(e.clientX, e.clientY)` —— touch 通道的 `handleUp()` 以 `onPointerUp({})` 调用，

### ★★ 多点触控无法用 adb 注入（重要限制）
